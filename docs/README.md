# Documentación de Specter

Índice de la documentación del proyecto. Se sigue un enfoque SDD (especificación → plan → tareas) y DDD pragmático.

| Documento | Contenido |
|---|---|
| [constitucion.md](constitucion.md) | Principios no negociables del proyecto |
| [spec.md](spec.md) | Especificación funcional del MVP: alcance, historias y criterios de aceptación |
| [plan.md](plan.md) | Plan técnico: arquitectura, estructura del repo, pruebas y despliegue |
| [tasks.md](tasks.md) | Tareas verificables con estimación y tiempo real |
| [dominio/lenguaje-ubicuo.md](dominio/lenguaje-ubicuo.md) | Glosario del dominio |
| [dominio/modelo.md](dominio/modelo.md) | Contextos, entidades, estados y reglas |
| [dominio/dudas.md](dominio/dudas.md) | Preguntas abiertas del dominio |
| [arquitectura/arquitectura.md](arquitectura/arquitectura.md) | Componentes, flujos y diagramas |
| [adr/](adr/) | Registro de decisiones de arquitectura (0001 a 0007) |
| [seguridad/seguridad-y-pendientes.md](seguridad/seguridad-y-pendientes.md) | Controles mínimos, riesgos y pendientes |

## Convenciones

- Markdown estándar con enlaces relativos (funciona en GitHub y en Obsidian).
- Los diagramas se escriben en Mermaid dentro de los propios documentos.
- Cada decisión de arquitectura relevante tiene su ADR numerado (`adr/NNNN-titulo.md`).
- Se distinguen **hechos**, **decisiones** y **supuestos pendientes de validar**.
